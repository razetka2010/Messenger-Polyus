# Полюс Messenger

**Полюс** — веб-мессенджер для личных переписок и сообществ. Приложение использует React, Vite, Express и SQLite; интерфейс доступен на русском и английском языках и адаптируется к мобильным экранам.

**Версия:** `1.4.0`

## Возможности

- Регистрация и вход по имени пользователя, отдельные аккаунты и сессии на одном устройстве.
- Личные чаты, группы с ролями, публичные и частные каналы.
- Предпросмотр общедоступных каналов и групп; настройка прав администраторов и авторства публикаций в каналах.
- «Избранное», ответы, реакции, пересылка, поиск и постраничная история сообщений.
- Вложения, изображения, видео, голосовые сообщения, ссылки и защищённая загрузка файлов.
- Публичные профили по адресу `/users/:username`: обложки, темы, собственные цвета и градиенты, шрифты, фон, рамки аватара, эффекты и анимации. Обложка может быть изображением, GIF, MP4 или WebM размером до 8 МБ.
- Общие чаты и медиа на страницах профиля. Публикаций, подписок, лайков и комментариев в приложении нет.
- Несколько тем интерфейса, русский и английский языки, поддержка настройки уменьшения анимации.
- Обновления в реальном времени через SSE и браузерные push-уведомления.
- Установка как PWA в совместимом браузере.

## Требования

- Node.js **20.19 или новее**.
- npm.
- Для push-уведомлений и публичного развёртывания — HTTPS.

На Windows для `better-sqlite3` иногда требуется среда сборки нативных модулей, если готовый бинарный пакет недоступен для установленной версии Node.js.

## Быстрый запуск на Windows

Откройте PowerShell в каталоге проекта:

```powershell
npm ci
$env:POLUS_ENCRYPTION_KEY = node -e "process.stdout.write(require('node:crypto').randomBytes(32).toString('base64url'))"
$env:POLUS_ENCRYPTION_KEY
npm start
```

Скопируйте выведенное значение и сохраните его в надёжном месте. При последующих запусках задавайте **то же значение** — не генерируйте новый ключ для уже созданной базы. Потеря или замена ключа может сделать недоступными запечатанные приватные ключи. Для постоянного запуска задайте его в окружении службы или в локальном `.env`, который не следует добавлять в Git. В репозитории нет `.env.example`; если нужен файл `.env`, создайте его вручную.

После запуска откройте <http://localhost:3000>. `npm start` сначала собирает клиент, затем запускает сервер.

Для разработки запустите сервер и Vite в отдельных терминалах:

```powershell
# Терминал 1
npm run server
```

```powershell
# Терминал 2
npm run dev
```

Откройте адрес Vite, обычно <http://localhost:5173>. По умолчанию Vite пересылает запросы `/api` на `http://localhost:3000`. Другой адрес можно задать переменной `POLUS_API_TARGET` перед запуском dev-сервера:

```powershell
$env:POLUS_API_TARGET = "http://localhost:3000"
npm run dev
```

## Конфигурация

Сервер читает `.env` из корня проекта при запуске. Переменные, уже переданные в окружение процесса, имеют приоритет. Для production используйте секрет-хранилище или настройки окружения службы.

| Переменная | Значение по умолчанию | Назначение |
|---|---|---|
| `HOST` | `0.0.0.0` | Адрес, на котором слушает Node.js. За reverse proxy обычно задают `127.0.0.1`. |
| `PORT` | `3000` | Порт Node.js-сервера. |
| `POLUS_ENCRYPTION_KEY` | Не задан | Случайный общий секрет сервера длиной не менее 32 байт. Необходим для функций шифрования и открытия запечатанных приватных ключей. |
| `POLUS_COOKIE_SECURE` | Выключено | Установите `true`, если HTTPS завершается на reverse proxy. Включает Secure-флаг cookie и HSTS. |
| `POLUS_TRUSTED_PROXIES` | Пусто | Список точных IP доверенных прокси через запятую. Используется для обработки `X-Forwarded-For`. |
| `POLUS_PUSH_CONTACT` | `mailto:admin@example.com` | Контакт оператора для VAPID/Web Push. Для публичного сервиса укажите настоящий контакт. |
| `POLUS_DAILY_UPLOAD_LIMIT` | `1073741824` | Суточная квота загрузок на пользователя в байтах; значение по умолчанию — 1 ГиБ. |
| `POLUS_API_TARGET` | `http://localhost:3000` в Vite | Цель прокси API-запросов в режиме разработки. |

Не помещайте настоящий ключ шифрования в клиентский код, репозиторий или публичные логи. Не меняйте ключ без плана переноса существующих запечатанных ключей.

## Развёртывание

Приложение рассчитано на постоянный Node.js-процесс и локальную SQLite-базу. Для публикации используйте схему:

**Клиенты → HTTPS reverse proxy → Node.js, доступный только локально.**

Пример конфигурации Caddy для домена:

```caddyfile
example.com {
    reverse_proxy 127.0.0.1:3000
}
```

Настройте окружение Node.js-службы, например в PowerShell:

```powershell
$env:HOST = "127.0.0.1"
$env:PORT = "3000"
$env:POLUS_COOKIE_SECURE = "true"
$env:POLUS_TRUSTED_PROXIES = "127.0.0.1"
$env:POLUS_ENCRYPTION_KEY = "<постоянный секрет не короче 32 байт>"
$env:POLUS_PUSH_CONTACT = "mailto:admin@example.com"
npm start
```

Замените секрет и контакт примера реальными значениями. Настройте reverse proxy так, чтобы он перезаписывал или корректно формировал `X-Forwarded-For`, и доверяйте только проверенным адресам прокси. Не открывайте порт Node.js в интернет, если перед ним стоит reverse proxy.

После обновления проекта необходимо установить зависимости, пересобрать клиент и перезапустить сервер:

```powershell
npm ci
npm run build
npm run server
```

`npm start` выполняет сборку автоматически. Если `/api/account/profile-design` или другой новый API возвращает `404`, вероятно, работает старая копия сервера, другой процесс или прокси направляет запрос не в тот экземпляр. Убедитесь, что обновлены и `server.js`, и клиентская сборка, а затем перезапустите именно тот процесс, на который проксируются API-запросы.

Не запускайте Vite dev-сервер как публичный production-сайт. Приложение не поставляется с адаптером Vercel Functions и не рассчитано на несколько параллельных экземпляров без отдельной архитектуры для базы, сессий и realtime-событий.

## Данные и резервные копии

- Рабочая SQLite-база находится в `data/polus.sqlite`; вложения и другие данные также сохраняются под `data/`.
- Старое хранилище `data/polus-store.json` может импортироваться при миграции; оригинал автоматически не удаляется.
- Не удаляйте `data/` при обновлении приложения и не публикуйте его через веб-сервер.
- Остановите приложение перед резервным копированием. Скопируйте весь каталог `data/` в защищённое место, включая базу и сопутствующие SQLite-файлы.
- Сохраняйте VAPID-ключи и `POLUS_ENCRYPTION_KEY` вместе с резервной копией, но отдельно от общедоступных файлов сайта.
- На POSIX-системах приложение ограничивает права на каталог и файлы данных. На Windows настройте ACL NTFS для учётной записи службы.
- Периодически проверяйте восстановление резервной копии и ограничьте доступ к ней.

## Безопасность и ограничения

### Сессии и аккаунты

- Сессии хранятся в `HttpOnly` cookie и действуют до 30 дней; автоматического продления нет.
- В настройках можно просмотреть активные сессии и отозвать их все. Смена пароля отзывает все сессии, в том числе текущую.
- Несколько аккаунтов на устройстве изолируются ключом слота `X-Polus-Account`; этот ключ не заменяет авторизационную сессию.
- Регистрация доступна публично. Ограничения частоты регистрации и входа не заменяют модерацию или регистрацию по приглашениям; часть лимитов действует в памяти одного процесса и сбрасывается при перезапуске.
- Ответ о занятом имени пользователя раскрывает, что такое имя уже зарегистрировано.

### Шифрование сообщений

- Шифрование и подпись выполняются клиентом. Новые сообщения подписываются ключом отправителя ECDSA P-256; контекст чата, отправитель и счётчик входят в аутентифицируемый контекст сообщения. Клиенты проверяют подпись, контекст и повторы счётчика; сервер проверяет подпись и контекст новых сообщений.
- Приватные ключи запечатываются с использованием общего `POLUS_ENCRYPTION_KEY`. Авторизованный клиент получает этот секрет от сервера.
- **Это не обеспечивает защиту от оператора или взлома сервера.** Сервер может получить общий секрет и выдать клиентам изменённый код, чтобы прочитать ключи и переписку. Не используйте приложение для сценариев, где сервер должен быть технически неспособен получить доступ к содержимому.
- При первом получении публичный ключ собеседника запоминается (TOFU). При изменении ключа клиент предупреждает пользователя. TOFU не защищает от подмены ключа при первом контакте; сверяйте отпечаток с собеседником по независимому доверенному каналу.
- Forward secrecy с ratchet-протоколом не реализована: долговременная компрометация приватного ключа может угрожать старым сообщениям, если доступны соответствующие сохранённые шифротексты.
- Содержимое вложений шифруется клиентом, в том числе по фрагментам. Серверу всё равно видны метаданные доставки: участники и идентификаторы чатов, время, активность, реакции, количество вложений и приблизительный размер шифротекста.

### Файлы и сеть

- Сообщение может содержать до 4000 символов и до 10 вложений. Максимальный размер файла — 100 МБ; стандартная суточная квота загрузок — 1 ГиБ на пользователя.
- Обложка профиля ограничена 8 МБ; принимаются изображения, GIF и видео MP4/WebM. Тип файла проверяется по сигнатуре.
- Вложения не проходят антивирусную проверку. Не открывайте файлы от неизвестных пользователей.
- Для production используйте HTTPS. HTTPS также требуется для браузерных push-уведомлений.
- Каталог `data/` содержит базу, VAPID-ключи и загруженные файлы. Ограничьте к нему доступ и не размещайте его в публичном web root.

## Конфиденциальность

Страница `/privacy` содержит информационную политику приложения, но не является юридической консультацией. Перед предоставлением сервиса другим людям владелец развёртывания должен проверить её, указать оператора и контактные данные, а также описать реальные сроки хранения и обработки данных.

## Подготовка к публичному запуску

- [ ] Проверить, что в репозитории и публичном web root нет `.env`, каталога `data/`, секретов и резервных копий.
- [ ] Настроить HTTPS, постоянный секрет шифрования и контакт оператора.
- [ ] Проверить reverse proxy, адреса доверенных прокси и недоступность порта Node.js извне.
- [ ] Решить, допустима ли открытая регистрация, и подготовить модерацию.
- [ ] Настроить права доступа к `data/` и защищённое резервное копирование.
- [ ] Проверить страницу `/privacy` и привести её в соответствие с фактическим развёртыванием.
- [ ] На целевой версии Node.js выполнить `npm ci` и `npm test`.
- [ ] Настроить постоянный запуск, журналы, мониторинг и проверенное восстановление резервной копии.
