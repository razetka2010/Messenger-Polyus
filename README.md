# Полюс

Полюс — веб-мессенджер для личных переписок и сообществ. В приложении есть аккаунты, личные чаты, группы, публичные и частные каналы, «Избранное», вложения, голосовые сообщения и браузерные push-уведомления. Интерфейс поддерживает русский и английский языки и адаптирован для компьютеров и телефонов.

## Возможности

- Аккаунты с уникальным `@username`, профилем, аватаром и настройками конфиденциальности.
- Личные чаты, группы с ролями, публичные и частные каналы.
- Предпросмотр публичных каналов до вступления; публикации в канале доступны владельцу и администраторам.
- «Избранное» для заметок и сохранения сообщений с вложениями.
- Сообщения, ответы, реакции, пересылка, поиск и постраничная история.
- Изображения, файлы, голосовые сообщения, медиа и ссылки в чатах.
- Realtime-обновления через SSE и push-уведомления браузера.
- PWA, пять тем оформления и русский/английский интерфейс.

Ограничения сообщений и файлов: до 4000 символов в сообщении, до 10 вложений на сообщение и до 100 МБ на файл. По умолчанию одному пользователю доступно до 1 ГБ загрузок в сутки.

## Требования

- Node.js **20.19 или новее**.
- npm, который поставляется с Node.js.
- Для производственного запуска с push — публичный HTTPS-адрес и корректный контакт оператора.

## Быстрый запуск

```powershell
git clone https://github.com/razetka2010/Messenger---Polyus.git
Set-Location Messenger---Polyus
npm ci
npm start
```

Откройте <http://localhost:3000>. `npm start` собирает интерфейс и запускает сервер. Данные и загруженные файлы сохраняются в `data/`; каталог создаётся при первом запуске.

На Windows установка `better-sqlite3` может потребовать средства сборки нативных модулей, если для вашей версии Node.js нет подходящего готового пакета.

## Разработка

Установите зависимости один раз:

```powershell
npm ci
```

Запустите сервер и Vite в отдельных терминалах:

```powershell
# Терминал 1
npm run server
```

```powershell
# Терминал 2
npm run dev
```

Откройте адрес Vite, обычно <http://localhost:5173>. Для другого адреса API задайте `POLUS_API_TARGET` перед запуском Vite.

Проверка, включая production-сборку:

```powershell
npm test
```

## Развёртывание

Для production сначала установите зависимости и соберите клиент, затем запускайте только сервер:

```powershell
npm ci
npm run build
npm run server
```

Запускайте приложение как постоянную службу с автоматическим перезапуском и журналированием. Не используйте Vite dev-сервер для публичного сайта.

Рекомендуемая схема: **интернет → reverse proxy с HTTPS → Node.js на loopback-интерфейсе**. Например, Caddy может проксировать домен с действительным публичным DNS и сертификатом:

```caddyfile
example.com {
    reverse_proxy 127.0.0.1:3000
}
```

Для личной сети без домена можно использовать IP-адрес компьютера и локальный сертификат Caddy:

```caddyfile
https://YOUR-LAN-IP {
    tls internal
    encode zstd gzip
    reverse_proxy 127.0.0.1:3000
}
```

Замените `YOUR-LAN-IP` на адрес сервера в локальной сети. Этот сертификат не является публично доверенным: установите корневой сертификат Caddy на каждое клиентское устройство или браузер. Такая схема предназначена для личного использования, не для общедоступного релиза.

Для такого размещения задайте настройки серверу через окружение службы. Пример PowerShell для текущего терминала:

```powershell
$env:HOST = "127.0.0.1"
$env:PORT = "3000"
$env:POLUS_COOKIE_SECURE = "true"
$env:POLUS_PUSH_CONTACT = "mailto:admin@example.com"
$env:POLUS_TRUSTED_PROXIES = "127.0.0.1"
npm run server
```

Замените `admin@example.com` на действующий адрес оператора. Переменные окружения **не загружаются из `.env` автоматически** — задайте их в конфигурации службы или перед командой запуска. Не публикуйте значения секретов.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `HOST` | `0.0.0.0` | Интерфейс прослушивания. При reverse proxy используйте loopback, например `127.0.0.1`. |
| `PORT` | `3000` | Порт Node.js-сервера. |
| `POLUS_COOKIE_SECURE` | выключено | Установите `true`, если HTTPS завершается на reverse proxy. Включает Secure-флаг cookie и HSTS. |
| `POLUS_TRUSTED_PROXIES` | пусто | Точные IP-адреса доверенных прокси через запятую. Только от них сервер принимает `X-Forwarded-For`. |
| `POLUS_PUSH_CONTACT` | `mailto:admin@example.com` | Контакт оператора, используемый Web Push/VAPID. Укажите настоящий адрес для production. |
| `POLUS_DAILY_UPLOAD_LIMIT` | `1073741824` | Суточная квота загрузок на пользователя, в байтах; по умолчанию 1 ГБ. |

Не доверяйте прокси-заголовкам от произвольных клиентов. Проверьте фактический адрес соединения между прокси и Node.js перед настройкой `POLUS_TRUSTED_PROXIES`. Не открывайте порт Node.js в интернет, если перед ним используется reverse proxy.

Публично доверенный HTTPS для сайта обычно требует доменного имени, публичной DNS-записи и доступности портов 80/443 для выдачи сертификата. Локальный сертификат Caddy, выпущенный для IP-адреса, подходит для личной сети только на устройствах, которым доверен локальный корневой сертификат; он не заменяет публичный сертификат.

Push работает только в HTTPS-контексте и после явного разрешения пользователя. Подписка создаётся отдельно в каждом браузере/профиле. VAPID-ключи создаются автоматически и хранятся в данных приложения — сохраняйте их при обновлениях.

## Данные и резервные копии

- SQLite-база, её служебные файлы и загруженные вложения находятся в `data/`.
- Старое хранилище `data/polus-store.json` импортируется при необходимости; исходный JSON не удаляется автоматически.
- Не удаляйте `data/` при обновлении приложения. Каталог исключён из Git.
- Для согласованной резервной копии остановите сервер, затем скопируйте **весь** каталог `data/` в защищённое место. Не копируйте только основной файл SQLite во время работы сервера: SQLite использует WAL.
- Периодически проверяйте восстановление резервной копии. Ограничьте доступ к каталогу и зашифруйте резервные копии на носителе.
- Незавершённые загрузки и просроченные сессии очищаются автоматически. Незавершённые вложения хранятся до 24 часов.

## Безопасность и ограничения

- **Публичная регистрация включена.** Ограничение частоты не заменяет регистрацию по приглашениям или модерацию; не открывайте сервер в интернет без готовности принимать новые аккаунты.
- Пароли хранятся в виде хешей с солью; сессии используют случайные токены в `HttpOnly` cookie со сроком до 30 дней. Смена пароля отзывает остальные сессии.
- Вход и регистрация ограничиваются по IP и username, но лимиты хранятся в памяти одного процесса и сбрасываются после перезапуска.
- Изменяющие API-запросы проверяют источник запроса. Для публичного сервера всё равно используйте HTTPS и корректно настройте reverse proxy.
- Доступ к сообщениям и вложениям групп и частных каналов ограничен участниками. Материалы, опубликованные в публичном канале, доступны публично.
- Вложения не проходят антивирусную проверку. Не скачивайте и не открывайте файлы от неизвестных пользователей.
- **Сквозного шифрования нет.** Оператор сервера имеет техническую возможность читать сообщения и доступ к загруженным файлам.
- Приложение рассчитано на один Node.js-процесс и локальную SQLite-базу. Оно не предназначено для запуска нескольких экземпляров за балансировщиком без отдельной архитектуры хранения и realtime-доставки.
- Страница `/privacy` — шаблон, а не юридическая консультация. Перед запуском для других людей укажите оператора, контакты, сроки хранения и политику, соответствующую вашему сервису и законодательству.
